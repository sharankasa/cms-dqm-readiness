# Readiness runs: engine inputs, readiness checks (R1) and scenarios (R2)

Credentialed data stays in AWS (Athena + S3); every script prints counts only (1–9 shown as `<10`).

| File | Role |
|---|---|
| `build_inputs.py` | Engine-input sets from a the prepare stage run: `cohort:<v>` (2017–2019 readiness cohort on mapping v), `changed:<v>` (cohort stays whose slice under v differs from mapping a: only these are re-evaluated), `all:<v>` (S2 full run), `s1-sample` (S2 timing sample, the S1 slices). Shards by predicted sliced time (`sql/10_sliced_runtime_model.sql`, `sql/20_select_and_shard.sql`), export in the the prepare stage format (`sql/30_export.sql`), plus V's input with one stay = one record (`--with-v`). For changed sets it lists the resource types that differ from mapping a (R2 holds everything but the mapping fixed) |
| `inputs_env.py` | Shell exports (`<SET>_INPUT`, `_ROOT`, `_TABLE`, `_V_INPUT`) for the newest build of each set |
| `run_check.py` | Is a run complete: every stay once per measure, no engine errors |
| `checks/make_requirements.js` → `checks/measure_requirements.json` | What each measure needs, from CMS's bundles: data requirements generated by fqm-execution (type, QI-Core profile, value set, status filter), declared value sets and whether the bundle carries their expansion, and the elements the CQL reads (units, timing, references, status) with the expressions that use them |
| `r1_run.py` | `universe` (`sql/50_r1_universe.sql`: the records the measures use in the cohort, baseline and as exported), `checks` (`sql/55_r1_checks.sql` on baseline and as exported, plus measure-level checks and declared profile families), `inject` (7 problem types × 1/10/50%, fixed nested seeds: recall and precision of each type's target check, all checks' flags kept), `scenario-inputs` (engine inputs for scenarios: injected copies, problems at their real full extent, medication status bounds, ICU glucose unit repair; `sql/40_scenario_export.sql`) |
| `r2_analysis.py` | R2 per mapping variant and scenario vs the baseline (2017–2019, mapping a): rates (CMS816 proportion with Wilson CI; CMS871 event days per 100 eligible days), 95% CIs of each rate and of the difference by a stay-level paired Poisson bootstrap (2,000 resamples, seed `dqm-r2-bootstrap-20261014`), stays entering/leaving each population, and the measure components (`defs`) that changed in moved stays. Counts 1–9 as `<10`; CMS816 rates with 1–9 events suppressed. SQL checked with SQLGlot and a mocked run |
| `launch_sets.sh`, `finish_sets.py` | Start the engine on several sets at once (detached, one node group) and finish + check them |

Tested on the open demo (2026-10-14, sandbox): scenario transforms → engine on changed stays → per-definition
components: ICU glucose unit repair moves 8 CMS871 stays (hyperglycemic event days); removing encounter →
diagnosis links moves 5 CMS871 stays out of the initial population. SQL parsed with SQLGlot (Trino dialect);
semantic errors surface on the first Athena run.
